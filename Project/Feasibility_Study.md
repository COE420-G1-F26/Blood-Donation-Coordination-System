## Technical Feasibility
The system can be developed with the resources and knowledge possessed by the team as its an inventory management system at its core. The detailed design and implementation of prototype phases should be doable with ease as all members of the team possess knowledge of Object oriented design and programming along with web development. High level design should be doable as long as we are not targeting extremely high rates of availability like 99.99999%. Although it is certainly within the team’s capabilities to educate themselves regarding design of such systems. Other phases of the project such as requirement analysis are material covered in the course, so this is doable by default.

## Economic Feasibility
The project should be very feasible economically as the project is software heavy with little to no hardware needed to develop it other than personal devices, and the deployment should be able to run on existing systems very easily.

## Operational Feasibility
The system is operationally feasible because it solves a real problem in managing blood inventory and blood requests. Blood banks can use it to keep track of blood types and quantities, organize donation drives, and register donors. Hospitals can use it to check what blood is available and request the amount they need. This can make the process easier and reduce some of the manual work. Since the system is based on tasks that blood banks and hospitals already do, the users should be able to understand and use it without much difficulty. 

## Schedule Feasibility
The project is schedule feasible because the system can be divided into different parts and the team members can work on them separately. For example, the inventory, donation drive, donor registration, and hospital request features can be developed separately and combined later. The project also has a clear scope, so the team can focus on the main features without adding too many extra requirements. With good task division and time management, we should be able to finish the required features and documentation within the course duration. 

## Overall Feasibility
In summary, the project is overall feasible because the team software skill matches the technical requirements of using programming and design of the project; moreover the team is able to learn and adapt new skills. Other phases of the project such as requirement analysis are material covered in the course to ensure the project is technically feasible. Secondly, the project is software-based, which significantly reduces hardware costs as we will not require significant hardware. The system solves a real problem and ensures each stakeholder is benefiting from the system. To elucidate, Blood bank & its staff tracks blood inventory and related information, hospitals request blood from available inventories, while donors give blood to the blood bank, and so on. In addition, division of the system into sub parts where each member can work on them separately and combine them later with the clear scope of core features & add-on ensures that the system can be done within the course duration. Altogether this project is feasible due to clear understanding of the project, team skills, minimal hardware requirements, and appropriate scheduling.
